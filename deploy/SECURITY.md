# Безопасность BotForge

## Проверенные границы приложения

Google OAuth использует state, nonce, PKCE и проверку ID-токена. Сессии хранятся как хеши токенов; cookie имеют Secure, HttpOnly и SameSite=Lax. Пользователь определяется сервером, а не полями проекта. Чтение, запись, удаление и экспорт требуют владельца проекта; SQL-запросы параметризованы. Публичный домен без OAuth-конфигурации не запускается в режиме общего локального пространства.

API ограничивает входящий JSON одним мегабайтом. Хранилище ограничивает рост аккаунта 200 проектами и 20 МиБ документов. Существующие данные не удаляются; уменьшение ранее превышенного объёма разрешено. Индекс владельца ускоряет изолированный список проектов. Сценарии исполняются ограниченным интерпретатором, без eval, доступа к файлам или выполнения команд из промпта.

Nginx должен передавать `X-Real-IP $remote_addr` с перезаписью пользовательского заголовка. Приложение доверяет этому заголовку только от loopback-прокси. Иначе один посетитель мог исчерпать общий лимит Google-входа для всех пользователей. Нельзя публиковать порт Node напрямую.

Регрессионные проверки: `node --test backend/*.test.cjs`. Проверки OAuth, владельцев, квот и восстановления также выполняются на отдельной копии баз — не через изменение настоящих проектов.

## Текущее усиление VPS

На VPS применены: SSH только по ключам; UFW с входящими 22, 80 и 443; ограничение соединений и запросов Nginx; HTTPS с HSTS и TLS 1.2/1.3; ограничения времени заголовков и тела запроса. Журнал сайта исключает query string, чтобы OAuth-коды не попадали в новые записи журнала.

Drop-in сервиса: `/home/botforge/.config/systemd/user/botforge.service.d/security.conf`. Включены NoNewPrivileges, PrivateTmp/PrivateUsers, ProtectSystem=strict, ProtectHome=read-only, ограничения памяти и процессов. Запись разрешена в `/home/botforge/botforge/data`. Обновляющий сервис работает отдельно, поэтому приложение не должно иметь права самостоятельно менять свой код.

Перед изменениями сохранены конфигурации Nginx/SSH/systemd, окружение и согласованные копии обеих баз. Указатель на каталог: `/root/botforge-security-current`. Копии доступны только root. Перед откатом следует сохранить более новые пользовательские изменения; не заменяйте живую базу старой копией без такой проверки.

`botforge-backup.timer` ежедневно запускает `/usr/local/sbin/botforge-backup`: SQLite backup API, integrity_check, семь последних копий в `/var/backups/botforge`. Нужен свободный объём для согласованной копии; при его нехватке операция завершается ошибкой. Копии на этом же VPS не защищают от потери самого сервера: внешний резервный адрес пока не подключён.

## Ограничения проверки

Это аудит доступного кода, конфигураций, пакетов, журналов, HTTP-границ, OAuth-проверок и резервного восстановления. Он не доказывает отсутствие всех возможных уязвимостей и не является криминалистической экспертизой или объёмным DDoS-тестом. Учётная запись облачного провайдера, независимый внешний backup и самостоятельная ротация внешних API-ключей требуют отдельного доступа. Секреты не должны попадать в репозиторий, отчёты или сообщения.
