# Развёртывание BotForge

Приложение запускается одним процессом Node.js 20+ за Nginx с HTTPS и Basic Auth. Это общее рабочее пространство команды с одним паролем, без отдельных аккаунтов и прав на проекты.

## Файлы и секреты

- Код релизов: `/opt/botforge/releases/<release>`; `/opt/botforge/app` — ссылка на активный релиз.
- Данные: `/var/lib/botforge/projects/botforge.sqlite` и сопутствующие WAL/SHM-файлы, вне релиза, принадлежат пользователю `botforge`.
- `/etc/botforge.env`, root:root 0600: `PORT=3000`, `DATA_DIR`, `PUBLIC_ORIGIN`, `AI_BASE_URL`, `AI_MODEL`, `AI_API_KEY`.
- `/etc/nginx/botforge.htpasswd`, root:www-data 0640: только хеш пароля входа. Не используйте пароль SSH для сайта.
- `botforge.service` запускает Node от отдельного пользователя, с доступом на запись только к данным и временному каталогу.

Ключи, пароли, `.env` и данные проектов не входят в Git и архив релиза.

## Установка

На Ubuntu установить Nginx, certbot, curl, xz-utils и ca-certificates. `install-node.sh` при отсутствии подходящего Node устанавливает официальный Node 22 для Linux x64 и проверяет SHA256 скачанного архива.

Создать системного пользователя `botforge` без shell. Подготовить `/etc/botforge.env` с настоящим HTTPS-origin. Установить `botforge.service` в `/etc/systemd/system/`.

В новый каталог релиза положить `server.js`, `storage.js`, `project.js`, `exporter.js`, `assistant.js`, `ai-project.js`, `package.json`, `package-lock.json`, каталоги `public`, `src`, `templates`. Выполнить:

```sh
npm ci
npm run build
npm prune --omit=dev
```

Создать `/opt/botforge/app` как ссылку на релиз. Выполнить `systemctl daemon-reload` и `systemctl enable --now botforge`.

До выпуска сертификата Nginx должен обслуживать HTTP challenge из `/var/www/botforge-acme`. Выпустить сертификат certbot webroot, затем заменить `__DOMAIN__` в `nginx.conf`, установить сайт и проверить `nginx -t`. Пароль обязателен для всего приложения, ACME challenge остаётся доступным для продления. После продления сертификата deploy-hook выполняет `nginx -t && systemctl reload nginx`.

## Проверка и обновление

- Без пароля HTTPS отвечает 401; с паролем приложение и API отвечают 200.
- Создать проект, сохранить, проверить восстановление после перезапуска службы.
- Проверить реальный запрос ИИ и ZIP всех четырёх языков. Ключ не должен присутствовать в ответах или статических файлах.
- `systemctl is-active botforge nginx certbot.timer` и `systemctl is-enabled botforge certbot.timer`.
- Логи приложения: `journalctl -u botforge`. Конфигурацию с секретами в логи не выводить.

Для обновления собрать новый релиз, переключить ссылку `/opt/botforge/app` и перезапустить `botforge`. Для отката вернуть ссылку на предыдущий релиз и снова перезапустить службу. Каталог данных не удалять. Перед изменением формата данных делать резервную копию `/var/lib/botforge/projects`.

## ИИ

Настройки задаются только на сервере. Включение `AI_API_KEY` активирует помощника; по умолчанию используются `https://triklz27.ru/v1` и `gpt-6-luna`. Проверить доступность модели через `/models` провайдера при изменении конфигурации.

UI сообщает, что описание и текущая схема отправляются провайдеру после явного нажатия кнопки. Модель возвращает только JSON-черновик; сервер проверяет блоки, связи, переменные и обязательные поля. Изменения применяются на клиенте после просмотра предложения и сохраняются отдельно. Автоматическая раскладка не использует API.

Один ИИ-запрос за раз, интервал минимум 10 секунд, до 12000 выходных токенов и 180 секунд ожидания. Провайдер может списывать баланс API. Ошибки провайдера не раскрывают тело ответа или ключ и не меняют проект.

Генерация запрашивает JSON-режим и низкий объём рассуждений. Ответ с `finish_reason=length` не применяется. Пояснения вокруг одного полного JSON допускаются, но несколько сценариев или незавершённый JSON отклоняются без изменения проекта.

## Переход с JSON на SQLite

Перед обновлением остановите сервис и сделайте копию всего `DATA_DIR`. При первом запуске JSON-проекты импортируются автоматически одной транзакцией; исходники не удаляются. Ошибка повреждённого проекта останавливает запуск без частичного переноса. Исправьте файл и повторите запуск. После успешного импорта приложение использует только SQLite. Откат на старый релиз потребует восстановления прежней копии данных: новые изменения в старые JSON не попадают.

Резервируйте каталог при остановленных процессах, включая WAL/SHM-файлы, если они есть. Не переносите один основной файл живой WAL-базы. При восстановлении используйте весь каталог одной копии. Для Node.js 20–26 используется better-sqlite3 12.x; если для платформы нет готового бинарного модуля, при `npm ci` нужны Python 3, make и компилятор C++ (на Ubuntu пакет build-essential).
